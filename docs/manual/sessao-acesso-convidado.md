| 6. Funcionamento | 1. O Shell abre em `start`, uma tela só com a cor de fundo.<br>2. `AppShell.OnLoaded` lê a preferência `calme.onboarding_done`. Se for falsa, vai para `//welcome` (onboarding).<br>3. Se for verdadeira, chama `SessionState.RestoreAsync()`: o valor `guest` restaura o convidado; um id válido com usuário no banco restaura o usuário logado (id e nome); um valor que não corresponde a nenhum usuário é apagado. Erro na leitura é tratado como "sem sessão".<br>4. Com sessão, vai para `//home`; sem sessão, para `//access`.<br>5. A marca de onboarding concluído é gravada ao exibir a tela de acesso e em `App.EnterHomeAsync()`, chamado após cadastro, login ou convidado.<br>6. "Continuar como convidado" grava `guest` no `SecureStorage` e abre `//home`.<br>7. No início, a saudação é "Olá, {nome}." para usuário logado e "Olá, que bom ter você." para convidado.<br>8. `SignOutAsync()` apaga a sessão do `SecureStorage` e limpa o estado em memória. |
| 7. Dependências e dados | • `SecureStorage` (MAUI): guarda só a chave `calme.session` com o id do usuário ou `guest`. Nunca guarda senha. No Windows não empacotado, o valor vai para `securestorage.dat` na pasta de dados do app (documentação oficial do .NET MAUI).<br>• `Preferences` (MAUI): chave `calme.onboarding_done`.<br>• `IUserRepository.GetByIdAsync`, para recuperar o nome do usuário (banco SQLite, ver "Infraestrutura do banco local").<br>• `SessionState` é singleton na injeção de dependência e é compartilhado por `App`, `AppShell`, `OnboardingPage`, `AccessPage`, `MainPage`, `SignupPage`, `LoginPage` e `AuthService`. |
| 8. Falhas e correção | • **Tela de boas-vindas aparecia ao reabrir.** Sintoma: ao reabrir com sessão, a tela de boas-vindas aparecia por um instante; nos testes funcionais, um clique em "Já tenho uma conta" caía na boas-vindas antes do redirecionamento e falhava com "Controle ausente: login-email". Diagnóstico: o primeiro `ShellContent` era o onboarding e a sessão era lida de forma assíncrona depois. Ajuste: `AppShell.xaml` l. 9–12 (tela neutra `start`) e `AppShell.xaml.cs` l. 29–33 (ida explícita para `//welcome`). Esperado: nenhuma tela de conteúdo aparece antes da decisão.<br>• **Ponto de atenção:** se o `SecureStorage` não conseguir ler o valor (chave de criptografia trocada ou arquivo corrompido), a sessão é apagada e o app abre na tela de acesso (`SecureSessionStore.cs` l. 12–17). |
